# Review until LGTM

Use this after implementation and ordinary review are complete. It is a GitHub observation loop, not a replacement for `review-until-green`, and it does not edit source or merge a PR.

Set `STATE_CLI` to the state script path before polling. A development checkout uses `plugins/concord/hooks/review-lgtm-state.js`; the optional Copilot shortcut is `${COPILOT_PLUGIN_ROOT}/bin/review-lgtm-state.js`. It is not required: use this Node-based locator, which searches only installed plugin caches and never the reviewed checkout, validates the Concord plugin manifest, and deterministically selects the newest installed Concord version: `node -e "const fs=require('fs'),p=require('path'),o=require('os'),q=[p.join(o.homedir(),'.claude','plugins','cache'),p.join(o.homedir(),'.codex','plugins','cache'),p.join(o.homedir(),'.copilot')],c=[];function a(f){let d=p.dirname(f);for(;;){try{const m=JSON.parse(fs.readFileSync(p.join(d,'.codex-plugin','plugin.json'),'utf8'));if(m.name==='concord'&&typeof m.version==='string')c.push([m.version,f]);return}catch{}const u=p.dirname(d);if(u===d)return;d=u}}for(const d of q){const s=[d];while(s.length){const x=s.pop();let z;try{z=fs.readdirSync(x,{withFileTypes:true})}catch{continue}for(const e of z){const f=p.join(x,e.name);if(e.isFile()&&e.name==='review-lgtm-state.js'&&['hooks','bin'].includes(p.basename(p.dirname(f))))a(f);if(e.isDirectory())s.push(f)}}}c.sort((x,y)=>x[0].localeCompare(y[0],undefined,{numeric:true}));if(c.length)console.log(c[c.length-1][1]);else process.exit(1)"`. Set its one-line output as `STATE_CLI`, then invoke every verb as `node "$STATE_CLI" <verb> ...` (PowerShell: `node $STATE_CLI <verb> ...`; cmd.exe: `node "%STATE_CLI%" <verb> ...`), never by executing the `.js` path. Its markers live in the repository git directory, are keyed by PR number and exact head SHA, and make interruptions resumable.

## Observe the current review

1. Resolve the exact PR head SHA before requesting or judging a review. Inspect only reviews, summary comments, threads, and reactions attached to that exact commit; ignore stale results.
2. A matching review is one authored by GitHub Codex and bound to that SHA, regardless of its state. Treat bot-authored summary activity naming that SHA as in-progress matching review activity when no review object exists; do not request another review. That matching review activity owns the full bounded window through its durable PR marker. When matching activity is first observed and `status` has no `deadlineMs`, immediately run `node "$STATE_CLI" open-window <pr> <head-sha> 900`; the initial request window bounds both an in-progress review and a completed review waiting for its reaction.
3. Read `node "$STATE_CLI" status <pr> <head-sha>` before requesting. If no matching activity exists, run `node "$STATE_CLI" claim-initial-request <pr> <head-sha>` before requesting the initial review. Request it only when the result is `{"claimed":true}`; a `false` result must poll or reconcile the existing marker, never send a duplicate request. A claim without a sent marker belongs to its original session for a 15-minute lease: the request operation must complete or be cancelled before that lease expires. Reconcile matching activity while that lease remains, then run `node "$STATE_CLI" recover-initial-request <pr> <head-sha>` after it expires. Send only when that recovery result is `{"claimed":true}`; if that recovery claimant also disappears, wait its 15-minute lease and recover again. After either successful claim, mark it sent and open the initial window. Run `node "$STATE_CLI" mark-initial-requested <pr> <head-sha>` and immediately `node "$STATE_CLI" open-window <pr> <head-sha> 900` only after the request succeeds. On resume, an `initialRequested` marker with no `deadlineMs` must open the same initial window before polling. Do not send a request on every poll.
4. Poll GitHub with the configured authenticated GitHub CLI profile. Record the latest matching review associated with the latest request, its completion state, its summary, unresolved threads authored by that bot, and whether that bot added the explicit LGTM reaction to that summary. Do not combine observations from separate reviews.
5. When the matching review completes, assemble one normalized observation for `record-review`: the review's numeric id, its URL, its `commit_id` — never an inline comment's `commit_id`, which can report a later commit than the review that created it — compared for exact-head matching against the PR's full `headRefOid`, `state` (`completed` or `in-progress`), the bot's LGTM-reaction presence, and one finding per unresolved bot thread plus one summary-level finding when the review body itself reports an issue, using the review URL. Parse each finding's priority from its P1 or P2 badge text, defaulting to `null` when neither badge is present, and tag any signals from the closed set (`lifecycle`, `ledger`, `audit-privacy`, `provider-parity`, `ac-conflict`, `unsupported-test`) that apply. Run `node "$STATE_CLI" record-review <pr> <head-sha>` with that JSON on stdin before any retry claim; recording must happen before any retry claim because the retry claim path is blocked only once a review record exists for the head.

## Decide and stop

Report green only when the matching review completed, its bot threads are resolved, and its summary has the configured LGTM reaction (for example, `THUMBS_UP`). A matching review that completed with no open bot threads but no LGTM reaction is `completed-without-lgtm`, not green.

`record-review` reports `needs-reconciliation` for any completed matching review with at least one unresolved bot thread or summary-level finding, even when the LGTM reaction is present; only a completed review with no findings and an explicit LGTM is green. Once a record exists for a head, `node "$STATE_CLI" status <pr> <head-sha>` carries the reconciliation packet, whose `classification` is `light-implementation-eligible` for a bounded light-implementation handoff or `requires-architecture-review` for an architecture-review handoff, and the claim verbs — `claim-initial-request`, `recover-initial-request`, `claim-retry`, `recover-retry-request` — return `{"claimed":false,"reason":"needs-reconciliation"}` for that head. Only a human decision or a new head resumes observation; do not edit source or merge a PR to clear a finding.

Continue polling only until the current persisted deadline (`deadlineMs` for the initial request, `retryDeadlineMs` for the retry); a resumed session must call `node "$STATE_CLI" status <pr> <head-sha>` and reuse it rather than starting another window. If the deadline arrives while the matching review is still in progress, stop with the named external outcome `review-timeout`; do not retry an unfinished review.

After the initial deadline, only a completed-without-LGTM review may run `node "$STATE_CLI" claim-retry <pr> <head-sha>` before requesting another review. Request the one retry only when it returns `{"claimed":true}`, then run `node "$STATE_CLI" mark-retry-requested <pr> <head-sha>` and immediately `node "$STATE_CLI" open-retry-window <pr> <head-sha> 900` after the request succeeds. A retry claim records `retryClaimedAtMs`. If a resumed session finds a retry claim but no sent marker, reconcile it only with matching GitHub activity created at or after that timestamp; the original matching review cannot satisfy retry reconciliation. If matching retry-era activity exists, run `node "$STATE_CLI" mark-retry-requested <pr> <head-sha>` and `node "$STATE_CLI" open-retry-window <pr> <head-sha> 900` without sending another request. Hold that claim for its 15-minute lease; only after it expires run `node "$STATE_CLI" recover-retry-request <pr> <head-sha>`, and send only when it returns `{"claimed":true}`. A recovery claimant that disappears is recoverable after its own lease. On resume, a `retryRequested` marker with no `retryDeadlineMs` must open the retry window before polling. A sent marker forbids another retry for that exact head. Once the retry deadline expires without LGTM, stop and report `completed-without-lgtm`; do not retry indefinitely. A new head SHA is a new observation attempt. Do not fabricate a reaction or modify code.

## Handoff

State the PR, exact head SHA, matching review completion state, open bot-thread count, LGTM-reaction presence, persisted window deadline, and retry-claim result. A `completed-without-lgtm` result must remain visibly not green. When a reconciliation record exists, state its classification and each finding URL instead of a bare completion state.
