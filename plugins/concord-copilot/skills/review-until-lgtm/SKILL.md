# Review until LGTM

Use this after implementation and ordinary local review are complete. It coordinates external automated PR feedback from Codex, Copilot, or another explicitly configured reviewer. It may fix, test, commit, and push review findings on the existing PR branch, but it never merges the PR or creates follow-up issues without user authorization.

Set `STATE_CLI` to the state script path before polling. A development checkout uses `plugins/concord/hooks/review-lgtm-state.js`; the optional Copilot shortcut is `${COPILOT_PLUGIN_ROOT}/bin/review-lgtm-state.js`. It is not required: use this Node-based locator, which searches only installed plugin caches and never the reviewed checkout, validates the Concord plugin manifest, and deterministically selects the newest installed Concord version: `node -e "const fs=require('fs'),p=require('path'),o=require('os'),q=[p.join(o.homedir(),'.claude','plugins','cache'),p.join(o.homedir(),'.codex','plugins','cache'),p.join(o.homedir(),'.copilot')],c=[];function a(f){let d=p.dirname(f);for(;;){try{const m=JSON.parse(fs.readFileSync(p.join(d,'.codex-plugin','plugin.json'),'utf8'));if(m.name==='concord'&&typeof m.version==='string')c.push([m.version,f]);return}catch{}const u=p.dirname(d);if(u===d)return;d=u}}for(const d of q){const s=[d];while(s.length){const x=s.pop();let z;try{z=fs.readdirSync(x,{withFileTypes:true})}catch{continue}for(const e of z){const f=p.join(x,e.name);if(e.isFile()&&e.name==='review-lgtm-state.js'&&['hooks','bin'].includes(p.basename(p.dirname(f))))a(f);if(e.isDirectory())s.push(f)}}}c.sort((x,y)=>x[0].localeCompare(y[0],undefined,{numeric:true}));if(c.length)console.log(c[c.length-1][1]);else process.exit(1)"`. Set its one-line output as `STATE_CLI`, then invoke every verb as `node "$STATE_CLI" <verb> ...` (PowerShell: `node $STATE_CLI <verb> ...`; cmd.exe: `node "%STATE_CLI%" <verb> ...`), never by executing the `.js` path. State lives in the repository git directory, keyed by PR number and exact head SHA, so interruption or session replacement does not reset a budget.

## Collect one head

1. Resolve the exact PR head SHA from the full `headRefOid`. Read only review objects, summary comments, threads, checks, approvals, and reactions attributable to that exact head; older-head feedback is history, not current evidence.
2. Run `node "$STATE_CLI" status <pr> <head-sha>`. When current-head matching activity first appears and `deadlineMs` is absent, run `node "$STATE_CLI" open-window <pr> <head-sha> 900`. The persisted 15-minute deadline bounds the whole collection, including in-progress reviewers and a completed review waiting for its signal.
3. Treat every automated reviewer explicitly requested on the PR or configured by the repository as part of the current-head batch. Do not start fixing when the first review arrives. Collect until every known automated reviewer is terminal. If GitHub does not expose a finite reviewer set, require 120 seconds with no new current-head review activity after the latest completion, still bounded by `deadlineMs`. Reaching the deadline with a known reviewer missing or in progress is `review-timeout`, not a complete batch or green.
4. If no matching activity exists, run `node "$STATE_CLI" claim-initial-request <pr> <head-sha>`. The first call starts a 120-second automatic-review grace and returns `auto-review-grace`; poll until `requestEligibleAtMs` so an automatic review is not raced by a manual request. Request through a configured provider only when the claim returns `{"claimed":true}`. Then run `mark-initial-requested` and `open-window <pr> <head-sha> 900`. On resume, if `initialRequested` is true but `deadlineMs` is absent, run `open-window <pr> <head-sha> 900` before polling. A claim without a sent marker has a 15-minute lease and may be recovered with `recover-initial-request` only after that lease. Manual requests have a durable budget of three for the whole PR; legacy sent-request markers count toward that budget, and a new head does not reset it. Stop on `request-budget-exhausted` and never delete markers, change the PR number, or start a new state directory to bypass it.
5. Normalize every current-head automated review before deciding. Map GitHub `APPROVED`, `COMMENTED`, `CHANGES_REQUESTED`, and `DISMISSED` reviews to `completed`; map pending provider activity to `in-progress`. Pass `reviewId`, `reviewer`, `reviewUrl`, the review's own full `commitId`, normalized `state`, `lgtm`, and all unresolved findings to `node "$STATE_CLI" record-review <pr> <head-sha>` on stdin. A finding contains its URL, P1/P2 priority when supplied or `null`, and applicable signals from `lifecycle`, `ledger`, `audit-privacy`, `provider-parity`, `ac-conflict`, and `unsupported-test`. Record every review in the collection batch even after one returns `needs-reconciliation`; never stop at the first reviewer and leave later feedback for another push.

An LGTM signal must be explicit and fresh for the current head: an automated GitHub `APPROVED` review, or that same reviewer's positive reaction created at or after its current-head terminal review or summary completion time, comparing timestamps at whole-second precision. Absence of findings is not itself LGTM. For Codex's clean no-review-object path, require no Codex review object for the full `headRefOid`, `status.reconciliation === null`, a `✅ Completed` summary row whose commit is a prefix of that head, and a `chatgpt-codex-connector[bot]` +1 reaction on the PR created at or after the row's completion time. A stale reaction never counts.

## Reconcile and fix one batch

An unresolved finding from any collected reviewer takes precedence over another reviewer's LGTM. Green requires the collection window to be complete, zero accepted current-head findings, and at least one fresh LGTM signal.

When findings exist:

1. Give the complete collected set to one clean-context verifier. It evaluates related or conflicting findings together, rejects false positives with evidence, deduplicates symptoms that share a root cause, and identifies repository-wide occurrences of the same pattern. Add a second independent verifier only for conflicting conclusions, security or data-boundary risk, or a proposed contract/architecture change.
2. Build one implementation plan for all accepted in-scope findings. Prefer one root-cause change that resolves several comments over comment-by-comment edits. Run `node "$STATE_CLI" claim-fix-round <pr> <head-sha>` immediately before editing. A reserved slot is resumable only when this command returns `claimed:true`, including `resumed:true` after an abandoned reservation's 15-minute lease. The three fix-and-push rounds are a PR-wide hard cap, not a quality guarantee; a new head does not replenish them. On `fix-round-budget-exhausted`, preserve the batch and stop for human reconciliation without claiming green.
3. Apply the whole plan before pushing. Run the smallest relevant regression checks once after the batch is complete, then create one commit and one push. Do not push after each comment. Resolve or reply to review threads only after the pushed change and checks support the response.
4. Resolve the new full head SHA and repeat collection for that head only. Never request a second full review on the same head solely to obtain a missing reaction. If a terminal review has no findings and no fresh LGTM by `deadlineMs`, stop as `completed-without-lgtm`.

Stop instead of fixing when an accepted finding changes the approved product contract, materially expands the PR, or requires unrelated architecture. Also stop when three fix rounds do not converge. If only minor, non-release-blocking issues remain, propose a single follow-up issue containing the batch and rationale; do not create it without user authorization and do not keep changing the PR merely to obtain theoretical perfection.

## Handoff

Report the PR, exact head, configured reviewers observed or missing, collection deadline, each recorded review's id, reviewer, URL and findings, fresh LGTM evidence, accepted and rejected grouped findings, checks run, commits pushed, and both budgets' max, spent, and remaining values. A timeout, exhausted budget, scope escalation, or `completed-without-lgtm` remains visibly not green. Report follow-up-issue candidates separately from release-blocking findings.
